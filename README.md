# Unnamed VPN — Telegram Bot (aiogram 3 + Crypto Pay + Platega)

Бот **только** управляет пользователями/оплатой/подписками. Выдача самого
VPN-доступа (создание/продление клиента) сейчас — ЗАГЛУШКА
(`services/vpn_provider.py`): интеграция с 3x-ui убрана, вместо неё
планируется подключение к собственному мастер-серверу, который будет сам
распределять клиентов по воркер-нодам. Пока он не готов, бот просто выдаёт
фиктивную ссылку-подписку, чтобы оплата/баланс/промокоды продолжали
работать и тестироваться.

## Возможности

- Регистрация пользователя при `/start`
- Карточка профиля (баланс, ссылка-подписка, срок действия) + меню в стиле
  «Подключить устройство / Продлить подписку / Баланс / Устройства /
  Поделиться подпиской / О сервисе»
- Баланс пользователя: пополнение через Platega/СБП (пресеты суммы + произвольная
  сумма) и оплата подписки прямо с баланса, без похода к провайдеру
- Выбор тарифа и оплата в USDT (или другом активе) через Crypto Pay API (@CryptoBot),
  либо в рублях через СБП (platega.io)
- После оплаты — создание/продление клиента у VPN-провайдера и выдача ссылки-подписки
  (сейчас это заглушка, см. `services/vpn_provider.py`)
- Промокоды 4 типов: бонусные дни, начисление на баланс, скидка % (в т.ч. 100% =
  бесплатно) на будущую покупку, партнёрский код (пробные дни + скидка % разом).
  Скидка учитывает лимит активаций, срок действия, один код — один раз на пользователя
- Ежедневная фоновая проверка: отключение доступа по истечении срока + напоминания за 3 дня
- `/stats` для админов (кол-во активных/истёкших подписок)

## Установка

```bash
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env`:

- `BOT_TOKEN` — токен от @BotFather
- `ADMIN_IDS` — ваш Telegram ID (через запятую, если несколько)
- `MASTER_API_BASE_URL` / `MASTER_API_TOKEN` — реквизиты будущего мастер-сервера
  (пока не используются, `services/vpn_provider.py` работает как заглушка)
- `CRYPTO_PAY_TOKEN` — токен из @CryptoBot → Crypto Pay → Create App
- `PLATEGA_MERCHANT_ID` / `PLATEGA_SECRET` — реквизиты из личного кабинета
  platega.io (Настройки), выдаются менеджером при подключении
- `VPN_NAME` — название сервиса, подставляется в тексты бота (по умолчанию "Unnamed VPN")

Запуск:

```bash
python main.py
```

## Что нужно донастроить под себя

1. **Подключение мастер-сервера**: сейчас `services/vpn_provider.py` — заглушка,
   она ничего никуда не отправляет и просто выдаёт фиктивную подписку. Когда
   мастер-сервер будет готов принимать клиентов — впишите его адрес/токен в
   `MASTER_API_BASE_URL`/`MASTER_API_TOKEN` и замените тело `ensure_client()`/
   `disable_by_email()` в этом файле на реальные HTTP-запросы к нему.
2. **Тарифы**: список в `config.py` → `PLANS` (название, дни, цена в USDT и в RUB —
   рублёвые цены сейчас проставлены примерно, поправьте под свой курс/маржу).
   Пресеты пополнения баланса — там же, `TOPUP_PRESETS_RUB`.
3. **Баланс/устройства**: устройства пока безлимитны по количеству — реальный
   лимит появится вместе с интеграцией мастер-сервера. Пополнение баланса сейчас
   идёт только через Platega/СБП (в рублях); если нужен топ-ап через CryptoBot —
   сообщайте, добавлю.
4. **Проверка оплаты** сейчас идёт по кнопке «Я оплатил» (polling у CryptoBot/Platega).
   Для мгновенного зачисления можно дополнительно поднять вебхуки —
   сообщайте, если нужно, добавлю обработчик на aiohttp/FastAPI.
5. **Промокоды** создаются/управляются админ-командами в Telegram (см. ниже),
   отдельной админ-панели нет.
6. **Platega (`services/platega_api.py`)**: реализация основана на
   официальной документации https://docs.platega.io/ (эндпоинт
   `POST /transaction/process` с `paymentMethod: 2` — СБП с QR-кодом,
   `GET /transaction/{id}` — статус). Перед боевым запуском сверьте формат
   ответа с актуальной документацией в личном кабинете — он мог измениться.

## Админ-команды (Telegram)

- `/stats` — количество активных/истёкших подписок
- `/promo_create КОД ТИП ЗНАЧЕНИЕ [max=N] [expires=YYYY-MM-DD] [uses=N] [valid_days=N]`
  — создать промокод. Типы:
  - `days` — бонусные дни подписки сразу: `/promo_create WELCOME7 days 7 max=100`
  - `balance` — начисление на баланс сразу (₽): `/promo_create SALE300 balance 300 max=50 expires=2026-12-31`
  - `discount` — скидка % на будущую покупку (100 = бесплатно). `uses` — сколько раз
    можно применить скидку (по умолчанию 1, `uses=0` = без лимита до истечения срока),
    `valid_days` — сколько дней скидка действует после активации (по умолчанию бессрочно):
    - `/promo_create FREEMONTH discount 100 uses=1 valid_days=3 max=50` — 100% на первую покупку в течение 3 дней
    - `/promo_create SPRING15 discount 15 uses=0 valid_days=30 max=500` — 15% на все покупки 30 дней
  - `partner` — то же самое, что discount, но ограничение "один раз на юзера"
    считается по ЛЮБОМУ partner-коду сразу (не по конкретному коду). Пробных
    дней не даёт — они и так выдаются автоматически на первом `/start`:
    - `/promo_create PARTNER15 partner 15 uses=0 valid_days=365 max=1000` — 15% скидка на год
- `/promo_list` — список всех промокодов со статусом и статистикой использования
- `/promo_disable КОД` — отключить промокод
- `/plans` — список тарифов с текущим статусом (включён/отключён) и ценой
- `/plan_disable КОД` — скрыть тариф из продажи (бот/мини-апп перестают его предлагать)
- `/plan_enable КОД` — снова включить тариф
- `/plan_price КОД ЦЕНА_RUB [ЦЕНА_USDT]` — изменить цену тарифа, например `/plan_price 1m 199` или `/plan_price 1m 199 2.49`
- `/plan_price_reset КОД` — вернуть цену тарифа к значению по умолчанию из `config.py`
- `/add_balance TG_ID_или_@username СУММА` — начислить/списать баланс пользователю
- `/user_info TG_ID_или_@username` — полная информация о пользователе: UUID, TG ID,
  username, баланс, скидка, доп. устройства, подписка, последние счета
- `/cmdlist` — список всех команд бота с кратким описанием
- `/set_vpn_link UUID_или_TG_ID_или_@username ССЫЛКА` — вручную привязать
  ссылку на VPN-ключ к подписке пользователя (пока `services/vpn_provider.py`
  — заглушка, этим можно подставлять ссылки, созданные руками на панели)
- `/reset_account UUID_или_TG_ID_или_@username` — **полностью** удаляет
  пользователя и все его данные (подписка, счета, использованные промокоды,
  токены входа) — необратимо, требует подтверждения кнопкой. После удаления
  tg_id снова считается новым пользователем: заново получит триал/реф.бонус
  на первом `/start`, промокоды можно погасить заново.

## Ссылка-подписка (/sub/&lt;token&gt;)

Пока нет мастер-сервера с per-user провижинингом, `services/vpn_provider.py`
остаётся заглушкой (см. её докстринг) — но сама ссылка-подписка, которую
получает пользователь, уже настоящая и рабочая, а не `example.com`-заглушка:

- `webapp/api.py` отдаёт `GET /sub/<token>` — `token` это `users.sub_token`,
  генерируется автоматически при создании пользователя (не палит tg_id/UUID
  в URL).
- Тело ответа — конфиги из `SUBSCRIPTION_NODE_LINKS` (по одной ссылке
  `vless://`/`hysteria2://`/... на строку), закодированные в base64. Сейчас
  сервера **общие для всех** пользователей — это ограничение до появления
  мастер-сервера с реальным per-user провижинингом.
- Заголовок `subscription-userinfo` даёт РЕАЛЬНЫЙ срок подписки конкретного
  пользователя (`expire=<unix timestamp>` из `subscription.expires_at`) —
  Happ/INCY/v2rayNG сами посчитают из него оставшиеся дни. `total=0` — трафик
  показывается как безлимитный (∞), т.к. per-node учёт трафика тоже появится
  только с мастер-сервером.

Нужно задать в `.env`:
```
SUBSCRIPTION_BASE_URL=https://vpn-bot-production-555c.up.railway.app  # без / на конце, публичный домен API
SUBSCRIPTION_NODE_LINKS=vless://...#Paris1
hysteria2://...#Paris1
```
(`SUBSCRIPTION_NODE_LINKS` — многострочное значение, каждая ссылка на своей
строке; в Railway это можно вставить прямо в текстовое поле переменной.)

⚠️ **Не используйте `unnamedvpn.dpdns.org` (или любой другой домен на
GitHub Pages) как `SUBSCRIPTION_BASE_URL`** — GitHub Pages чисто статический
хостинг и не умеет проксировать запросы на Railway, `/sub/<token>` там
всегда будет 404. Если нужен красивый домен вместо `up.railway.app` — либо
добавьте **отдельный поддомен** (например `sub.unnamedvpn.dpdns.org`) как
Custom Domain прямо в Railway (Settings → Networking → Custom Domain) с
CNAME-записью у регистратора, либо переносите фронтенд на Vercel/Netlify,
где рабочий rewrite/proxy в принципе возможен.

После смены `SUBSCRIPTION_BASE_URL` у пользователей, получивших подписку
**до** этого, в базе остаётся старая (нерабочая) ссылка — прогоните
`/backfill_sub_urls`, чтобы пересчитать её всем разом.

## Реферальная программа

Каждый пользователь получает свою ссылку `https://t.me/<bot>?start=ref_<TG_ID>`
(раздел «О сервисе» → «Реферальная программа» в боте). Когда по ней впервые
запускает бота новый пользователь, начисляются два бонуса на баланс:
рефереру — `REFERRAL_BONUS_RUB` (по умолчанию 15₽, с уведомлением в чате),
самому приглашённому другу — `REFERRAL_INVITEE_BONUS_RUB` (по умолчанию 49₽,
сообщением прямо в ответ на его `/start`).

Начисление одноразовое на каждого приглашённого (проверяется по факту первого
`/start`, самоприглашение и повторный `/start` существующего пользователя не
засчитываются). `/user_info` показывает, кем приглашён пользователь и сколько
пригласил он сам.

## Промокоды

Тип `partner` теперь даёт **только скидку** (ЗНАЧЕНИЕ = %, как у `discount`) —
пробных дней он больше не выдаёт, потому что триал теперь и так автоматом
выдаётся на первом `/start` (см. ниже), дублировать его через partner-код
не нужно. Ограничение **один раз на пользователя в принципе** — если человек
уже погасил любой partner-промокод, повторно активировать другой partner-код
(даже другой, с другим процентом) нельзя. Остальные типы
(`days`/`balance`/`discount`) по-прежнему ограничены только per-код (один и
тот же код нельзя погасить дважды одному пользователю).

## Бесплатный пробный период

При самом первом `/start` (пользователя ещё нет в базе) автоматически
выдаётся `TRIAL_DAYS` (по умолчанию 3) дней доступа — ссылка-подписка
приходит сразу тем же сообщением. Настраивается через `.env`
(`TRIAL_DAYS=0` отключает). Не мешает промокоду/реф-ссылке — если новый
пользователь одновременно переходит по `?start=promo_...` или
`?start=ref_...`, всё применяется одним и тем же первым `/start`.

## Мини-приложение (Telegram Mini App / WebApp)

Личный кабинет как полноценное веб-приложение внутри Telegram: баланс, подписка,
покупка/продление тарифов, промокоды, устройства — то же самое, что в меню бота,
но в виде интерфейса.

- **Backend** (`webapp/api.py`) стартует вместе с ботом (тот же `main.py`), слушает
  `API_HOST:API_PORT` (по умолчанию `0.0.0.0:8080`). Наружу нужно пробросить через
  reverse-proxy (nginx/caddy) с HTTPS на отдельном домене — без HTTPS Telegram WebApp
  не сможет к нему обратиться.
- **Frontend** (`webapp-frontend/`) — статический сайт, деплоится отдельно
  на Vercel/Netlify. Инструкция — в `webapp-frontend/README.md`.
- Авторизация — через `initData`, который Telegram сам подписывает на клиенте;
  backend проверяет подпись на каждый запрос (см. `webapp/auth.py`), отдельных
  логинов/паролей не требуется.

Настройка в `.env`: `WEBAPP_URL`, `WEBAPP_SHORT_NAME`, `API_HOST`, `API_PORT`,
`API_CORS_ORIGIN` (см. `.env.example`). Если `WEBAPP_URL` не задан — кнопка
мини-приложения просто не появится, бот продолжает работать как обычно через меню.

**Прямая ссылка на приложение для промокодов.** Кнопка «🎁 Активировать» у
промокодов открывает мини-приложение напрямую (минуя чат с ботом), если задан
`WEBAPP_SHORT_NAME`. Чтобы получить short name:

1. Откройте `@BotFather` → `/mybots` → выберите бота → `Bot Settings` →
   `Mini Apps` (или `Configure Mini App` в новых версиях) → создайте приложение,
   указав тот же URL, что и в `WEBAPP_URL`, и задайте короткое имя, например `app`.
2. Впишите это имя в `.env` как `WEBAPP_SHORT_NAME=app`.
3. Перезапустите бота.

Без этой настройки кнопка «Активировать» по-прежнему работает — просто
открывает чат с ботом и активирует промокод там (старое поведение).
